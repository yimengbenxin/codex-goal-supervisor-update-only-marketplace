日期：2026-07-11

## 目的

本文件只记录实际测试运行，不重复代码修复说明。主修复与原因见 `GOAL_COMPASS_PACKAGING_MANUFACTURING_STRESS_20260711.md`。

## 调度方式

- 实际创建并轮换了 30 个独立子智能体测试席位。
- 当前 Codex runtime 同时活跃上限为 4，因此按四路并发、完成即释放、下一行业补位的方式运行。
- 插件协议本身没有部门数量上限；超过 4 个部门仍必须由 CEO 对精确 roster fingerprint 确认。
- 所有行业测试者只读插件源码，在独立 `/tmp` 或专用测试目录中运行，不允许修改或回滚插件。
- 早期测试碰到源码正在被主线程修复时，报告会注明快照漂移；最终结论只绑定稳定源码哈希。

## 运行中曾发现的共同问题

多个行业独立复现了同轴疲劳误报：标签、气雾罐、玻璃、无菌复合、木质包装和医疗包装在不同工艺轴之间切换后，仍因模板词或文件格式词告警。主线程修复后，保护性缓冲、冷链、高端礼盒等稳定源码轮次未再报告该问题，统一 14 行业基准的 14 组不同工序也全部为 `axis_advisory=OK`。

多个黑盒测试者都报告 `runtime_execution_verified=false`。这是诚实的：这些 fixture 通过 CLI 验证 company roster、模型路由和 CEO 门，但 CLI 无法看到当前 Codex 主线程实际调用的子智能体工具。本次测试确实启动了独立子智能体，但没有把外部测试线程伪记成某张 fixture ticket 的执行证据。

最后两路还发现并推动了两个修复：化妆品包装复现了非 Git `artifacts/**` 精确路径旁路，Bag-in-Box 复现了 `NEEDS_VALIDATION` 掩盖 Janitor `NOISE_RISK`。两者都已加入 verification，并在最终统一基准中复验。

## 证据边界

- 统一机器基准的可分发证据位于 `docs/GOAL_COMPASS_PACKAGING_MANUFACTURING_STRESS_20260711.json`。
- 独立子智能体的完整原始命令多位于本机 `/tmp`，数量大且包含临时 fixture，因此不塞进插件 ZIP。
- 本报告保存量化摘要和证据路径类型，不把临时文件当作跨设备永久证据。
- 最终 ZIP 解压后会再次运行 verification 与 selftest，以验证可分发包而不只是源目录。
